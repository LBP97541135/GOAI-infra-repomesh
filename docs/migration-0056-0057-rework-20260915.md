## 你需要做什么

### 情况 A：本地库从来没跑过被删的两个旧迁移

什么都不用做，`alembic upgrade head` 即可。

### 情况 B：本地已经跑过旧的 0056 pgvector 迁移或 355278cd7ee4

旧文件已经不在仓库里，直接 `upgrade head` 会报"Can't locate revision"。
先重新盖章再升级：

```bash
alembic stamp 20260914_0056
alembic upgrade head
```

说明：`stamp` 只改 `alembic_version` 表里的版本号，不动表结构。旧迁移
加过的列（比如当时的 JSONB→vector 原地改列尝试）如果还留在你的库里，
0057 的 `ADD COLUMN IF NOT EXISTS` 会自动跳过重复项，不会报错；只有
JSONB `embedding` 列和 0057 期望不一致时才需要手动处理——遇到报错把
`alembic current` 和报错原文发群里，一起看。

### 情况 C：全新环境 / 删库重来

直接 `alembic upgrade head`，一步到位。

## 代码侧需要知道的

- `PgVectorDecisionEmbeddingStore` 现在双写：向量列走 `CAST(:vector AS vector)`，
  JSONB 副本走 `CAST(:embedding AS jsonb)`——是两个独立参数。asyncpg 无法
  对同一个参数同时推断 jsonb 和 vector 类型，这是修过的真 bug，别再合并回去。
- ORM 里 `DecisionEmbeddingRecord.embedding` 仍是 JSON 类型；物理向量列只
  允许显式 `CAST(... AS vector)` 的 SQL 访问。
- 没装 vector 扩展的环境会自动降级成 JSONB + Python 排序，`nearest()` 返回
  `None` 是"降级"不是"报错"，调用方会兜住。
- 嵌入模型是 BAAI/bge-m3，1024 维。换维度 = 新迁移 + 全量重嵌入，不要原地
  改列。
