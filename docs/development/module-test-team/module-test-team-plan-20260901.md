每波交付物、验证方式、依赖写死；波内条目可并行，波间按依赖表推进。

## 总览

```text
W0a 前置检查 P-1（DinD 实测）──────────┐
W0b 测试资产仓建仓注册 ────────┐      │
                               ▼      │
```

## W4 活体验收（验收标准 B/C/D 组）

前置：W0a PASS、W1~W3 完毕、新栈活体在位。

执行顺序（就是验收标准的执行顺序）：

1. **AC-D1**：走 UI 给测试资产仓贴档（= 拨开关，一动作双验）。
2. materialize 新项目 → 测试团队成立（A 组已自动化，此处顺检 AC-D2 徽标、AC-D3
   列表与房间）。
3. **AC-B1 绿轮**：Manager 派绿组合联调任务（判据含组合），worker 完整闭环。
4. **AC-B2 红轮**：红组合，FAIL + request-id 穿失败仓 + 判据未动。
5. **AC-B3**：核对两轮台账与房间路由。
6. **AC-C1 阻塞轮**：钉不存在的 commit。
7. **AC-C2 清扫双向**：伪造超时/新鲜残留各一，开工清扫后核对。
8. 执行记录表逐条填写（含证据指针）；任何 FAIL 记名，不停在模糊状态。

## 改道条款（P-1 FAIL 时）

- 联调执行改道 runner 轨：W3 的环境配方改写为 runner 侧任务模板（独立容器建组合、
  跑场景、逐条回执），worker 的 `integration-run` 技能从「自建自拆」改为「经批准入口
  发起 governed run 并守候回执」。
- W4 的 B/C 组按 runner 形态重写执行步骤；A/D 组与 W1/W2 交付物**原样有效**。
- 改道本身回设计稿留痕（§5.2 预案生效），并同步验收标准。
