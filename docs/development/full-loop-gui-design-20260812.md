## ① 仓库页 · 添加仓库（批次 A）

- 入口：仓库页头部右侧「添加仓库」按钮 → 内嵌卡片（非全屏遮罩）。
- **一个 URL 输入框走天下**：贴组织链接或单仓链接均可。识别的**单一事实源在
  后端**（detect_platform 是 Python，前端不镜像判定逻辑防漂移）：A-0 顺带出
  轻量识别端点，前端防抖调用，徽标以后端响应为准，等待期显示「识别中…」
  （2026-08-12 裁决，GUI完整版v3 发现的不一致处 #2）。
- **token 不进 GUI**（已定）：私有仓凭据由服务端 env 配置，界面文案明说。
  **console 转发端点白名单字段、不透传 `github_token`/`gitlab_token`**——原生
  RI 端点保留这两个字段（脚本/运维合法用途），但 console 面必须掐断这条旁路，
  契约里明写（裁决，不一致处 #1）。
- **失败仓不逐个回显**：进度行文案如实写「失败 N（详情见服务端日志）」；
  安全的失败清单回显（哪些错误可以给调用方看）进 backlog——出站错误不回显
  是 S-2 的安全教训，不为便利开倒车（裁决，不一致处 #3）。
- 长任务：提交后 202 + 轮询；进度行内展示「扫描中 n/m · 已注册 · 跳过（已存在）
  · 失败」，用户可离开该页回头再看。
- 失败处置＝裁决 1：结果区只给「重新扫描」整体动作；重扫幂等。

## ② issue 详情页 · 发现面板（批次 B）

- 四步步进器钉在面板顶部：`1 需求分析 → 2 候选评分 → 3 分档审批 → 4 生成计划`，
  态色：完成=橄榄绿、当前=琥珀、未到=弱化。任何时候进入都能看出走到哪。
- Step 1 需求分析：判定「不充分」时展示追问问题列表（clarify 回归），
  两条出路：a) 面板内问答表单，回答拼进需求重新分析；b) **强行继续**＝裁决 2，
  按钮点击即在决策记录留痕「忽略 N 条追问继续」。
- Step 2 候选评分：每仓一行——mono 仓名 + 评分条 + 分数 + 分档下拉。
  **LLM rationale 原样展示**（诚实数据原则的审批场景延伸），不摘要不美化。
- Step 3 分档审批：分档调整用行内下拉（required/maybe/excluded），不做拖拽分栏。
  审批主体沿用花名册派生（org leader），幂等键随表单生成（沿 A1/A7 模式）。
- 空态/失败态照诚实口径：LLM 调用失败显示错误原文摘要，不显示假进度。

## ③ DAG 面板 + 物化开工（批次 C，含原 #22）

- **批次泳道布局**，不做力导向自由画布：DAG 按 execution_batches 分列，
  列内节点垂直排布，边只画 depends_on。批次列直接对应执行顺序。
- 皮肤：阿波罗飞行计划风格的奶油纸面（Variant D 已有 DAG·计划纸面视图，
  本面是其「真实源」升级——数据从发现链产出而非回放夹具）。
- 节点状态着色复用现有 skin 表：橄榄绿=已交付、琥珀=进行中、弱灰=等待。
  执行期轮询刷新着色。
- **歧义节点留痕**：M-9 解析为 None 的名字显示为虚线节点 + 警示徽标，不隐藏。
- 只读＝裁决 3：无增删边/调批次交互；「调整」动线=返回 Step 3 改分档重新生成。
- 「物化并开工」：整条链第二个不可逆感知点（第一个是 merge 审批）。
  实心主按钮 + 确认弹窗，弹窗明说将创建 N 任务、组建 M 团队（每仓一队+双房间）。
- 前置勘误提醒：实现前先读 `ba38004`——DAG 边语义已变（同名解析 None、
  节点边同口径），原型期「graph_edges 恒空」的假设已过期。

## ④ 回滚对话框（批次 E）

- 挂载点：轮次面板交付卡上的「回滚」动作（仅 change set 存在已发布候选时可见）。
- 对话框主体是**范围表**，不是确认文案：每仓一行——仓名 / 当前态（未 merge、
  已 merge）/ 对应动作（withhold 免费撤回 / revert PR 逆序第 k 步）。
  把三阶段回滚设计翻译成用户语言。
- 琥珀提示条如实交代：revert PR 仍需过 CI 与门禁；冲突自动开冲突处理任务。
  **不许诺「一键干净还原」**。
- 按钮语义如实：提交的是 `ROLLBACK_REQUIRED` 治理决策（先堵死 merge gate），
  执行由机器在决策通过后接管（批次 D 的 saga）。
- 粒度＝裁决 4：整 change set 一体回滚，无单仓选择框。
