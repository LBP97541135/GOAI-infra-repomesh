PR 0 后固定的裁决

当前是待落实基线;PR 0 修正 ADR 和 contract 后冻结。

  1. Bridge 是独立进程;需要改 Runner 语义 = 升 Runtime v2,另行 ADR。
  2. 外部 Worker 走 containerManaged: false,Go Controller 零改动。
  3. Bridge 是深模块;外部 interface 只有 RoomNativeAgent.run(enrollment),内部真实 seam 是 Worker binding、room、coding session 和 governed task。
  4. CodingSessionPort 直接消费 ProtocolDriver.execute;PR 5 复用完整 Runner 执行链,不重写执行器、测试和提交逻辑。
  5. Bridge 兼任该 Worker 的 Runner consumer,不起第二个本地 Runner;控制凭据必须 Worker-scoped。
  6. 房间只收 repomesh.room-observation.v1 allowlist 投影;THINKING、协议帧、未脱敏输出永不入房。
  7. deny-all 不是隔离;真实 CLI 必须经受限 ProcessFactory 启动,隔离 probe 失败则只允许 fake。
  8. 允许 Runner composition root 做保持默认行为的注入式小改;Runtime v1 wire、ProtocolDriver interface、Go Controller 和前端不改。
  9. 实验分支只取设计与测试场景,禁 cherry-pick 它的 driver 与 projector。

PR 5

复用完整 Runner 链的受治理执行

6–10 人日

Bridge 兼任该 Worker 的 Runner consumer,但组合现有任务源、执行器、证据收集、事件 sink 与 ledger;房间进度是 Room Observation,不伪造尚未发布的 Runtime progress event。

组合既有深模块,不复制 seam

  • adapters/governed_task.py 调用 start_assigned_task;RepoMesh 校验 Task/assignee
  • runner_consumer.py 组合 HttpLongPollTaskSource、serve/ExecuteRunnerTask、DriverExecutor、HttpEventSink、TaskLedger
  • tests/agent_bridge/test_governed_execution.py
  • src/repomesh_agent_bridge/ports.py 只补 GovernedTaskPort;复用 Runner 已有 TaskSource/RunnerEventSink
  • src/repomesh_runner/executor.py composition root 可注入 ProcessFactory/observer,默认不变
  • modules/agent_runtime/api/router.py Worker-scoped lease/event auth
  • integrations/runner/{worker_execution,dispatch,task_projection,gateway}.py · workspace/git_worktree.py 复用,预期零改动或小改

验收(八条,全自动化)

  • 普通聊天要求改代码 → 拒绝并提示走 Task
  • 非 assignee 不能启动
  • allowed path 之外的改动失败
  • 测试失败不创建 commit
  • 相同 Task 重投复用 in-flight Run
  • 房间文本"完成"不推进 Task,只认 Runner 终态事件
  • Bridge token 改写 Worker 或投递其他 Worker 的 run event → 401/403
  • Matrix + Runner 两循环任一失败不留子进程、不丢 cursor

风险与缓解

#风险缓解
R1Enrollment 身份/连接不足PR 0 补 workerAgentId、homeserver URL 与 binding schema;PR 1 preflight 校验
R2凭据交付本机 keyring/env 引用 + 人工放置 token;不做在线秘密交换,日志不展开引用值
R3Matrix 重放 / 崩溃一致性PR 3 用 inbox + outbox + deterministic txn 覆盖三个 crash window
R4协作式权限被误当隔离受限 ProcessFactory + sentinel 测试为硬门禁;probe 失败拒绝真实 CLI
R5Worker 越权领取/回写Worker-scoped token;服务端从认证主体派生 Worker,不信任 query/body 自报身份
R6Windows 差异(CRLF / MSYS / ACL / 进程树)Windows-first 活体 isolation test;Linux adapter 后续;估算取上限
R7实验分支漂移只取场景与设计;禁 cherry-pick driver / projector
R8双 Runner 消费者竞争Bridge 兼任 consumer;compose 不加第二 Runner;同 Worker 启动锁 fail-fast

每个 PR 的统一合并门禁

  1. interface 行为测试先于实现细节测试;不得用目录结构断言替代行为验收。
  2. 每个外部副作用具备幂等键或 retry policy;新增远程 seam 同时有 production 与 in-memory/test adapter。
  3. ruff check . 与 pytest 全绿;真实 Matrix/Codex smoke 独立标记,无凭据时明确 skip。
  4. 扫描日志、fixture 与 Enrollment,确认无 token、系统提示、THINKING、原始协议帧或绝对私有路径。
  5. 跨模块只依赖 repomesh.modules.<producer>.contracts;composition root 才连接具体 adapter。
  6. PR 描述列出验证证据、回滚方式和剩余风险;禁止混入当前工作区无关改动。
