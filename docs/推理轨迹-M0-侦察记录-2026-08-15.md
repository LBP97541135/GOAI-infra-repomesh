M0 已闭环。真实会话文件存在且可读取，CoPaw 会话 JSON 的结构在真实数据上确认到字段级，四类赛题覆盖项的识别载体清晰：**chat** 与 **tool**（含 skill/mcp 前缀工具）从消息块直接提取，**rag** 依赖后续检索类工具调用或 memory 检索记录（真实数据中尚未出现，识别规则保留可扩展）。数据通道为 MinIO `hiclaw-storage` bucket，会话按 `agents/{name}/.copaw/workspaces/{workspace}/sessions/{session_id}.json` 同步，**workspace 名不固定**（`default` 与 `CoPaw_QA_Agent_0.1beta1` 并存）。

## 3. 真实会话结构（已确认，含样例）

基于 `agt-leader-3a15e2e1daed` 的两个真实会话（116 / 108 条消息）确认：

```
session.json
└── agent (dict)
    ├── name: str                 # "Friday"
    ├── _sys_prompt: str
    ├── toolkit: {tools: [...]}   # 已注册工具清单
    └── memory (dict)
        ├── content: [ [msg, []], ... ]     # 二元组列表，元素 1 恒为 []
        └── _compressed_summary: str        # 压缩摘要（长会话）
```

消息 `msg`（六个键，全部出现）：

| 键 | 说明 |
|---|---|
| `id` | 消息 id |
| `name` | 发送者（`default`=用户侧 / `Friday`=agent / `system`） |
| `role` | `user` / `assistant` / `system` |
| `content` | 块列表 |
| `metadata` | 本环境恒为 `{}`（空，勿依赖） |
| `timestamp` | 形如 `2026-08-14 11:43:10.386`（无时区） |

块类型（真实数据统计：text 4 / tool_use 56 / tool_result 56）：

| 块 | 所在消息 | 字段 |
|---|---|---|
| `text` | 任意 | `{type, text}` |
| `tool_use` | `role=assistant` | `{type, id, name, input, raw_input}`（`raw_input` 是 input 的 JSON 字符串） |
| `tool_result` | `role=system` | `{type, id, name, output: [text块, ...]}`（`output` 是块列表，非字符串） |

会话流模式：user 消息 → assistant 的 tool_use → system 的 tool_result → …；真实会话中 assistant 只发 tool_use（无纯文本回复），两个会话均为「探查 + shell 执行」形态。

## 5. 任务关联（重要情报）

user 消息文本是 Matrix 消息：`@agent:matrix-local... {JSON}`，其中 JSON 是 `schema: repomesh.collaboration.v1` 的结构化协作负载，含 `kind: task_assignment`、`task_id`、`correlation_id`、`project_id`、`repository_id`、`sender/recipient_agent_id`、`subject`。**推理轨迹由此可与 RepoMesh 任务体系关联**（task_id → issue/task），这是方案文档「trace ↔ issue 关联」的落点。

## 7. 读取通道评估（RepoMesh 采集器如何拿到会话）

宿主机访问 MinIO 的尝试结果：

| 通道 | 结果 |
|---|---|
| 宿主 `127.0.0.1:9000` | 未监听（MinIO 在 controller 容器内） |
| `127.0.0.1:18001` | Higress 控制台；S3 ListObjects 响应非标准 XML，minio 客户端不可用 |
| `127.0.0.1:18088` | Element Matrix Web UI，非 MinIO |
| Windows WSL 卷路径（`\\wsl.localhost\...agentteams-data`） | 不可访问 |
| controller 补 9000 端口映射 | 需要重建 controller 容器（影响 AgentTeams 环境） |

可用方案（按推荐序）：
1. **docker exec 桥接**（当前环境立即可用）：采集器/同步脚本执行 `docker exec agentteams-controller mc cp -r local/hiclaw-storage/agents/ <容器内路径>`，再 `docker cp` 到宿主 STORAGE_ROOT；或一次性容器挂 `agentteams-data` 卷把 `minio/hiclaw-storage/agents` 拷贝到宿主目录，采集器走本地直读。
2. **MinIO 端口映射**：给 controller 加 `-p 9000:9000`（重建容器），采集器直接用 minio 客户端（方案文档的 S3 模式），凭据已知。
3. 比赛部署若为容器内 RepoMesh 与 controller 同网络，则直接访问 `agentteams-controller:9000`，无需映射。
