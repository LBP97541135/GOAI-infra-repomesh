## 二、已完成的文件清单

### 2.1 datasets/train-ticket/validation_cases.json

15 个测试用例，JSON 数组格式。每个用例包含：

```json
{
  "id": "TT-001",
  "source_commit": "5b9edca5...",
  "requirement": "修复订票和取消订单流程中发送通知邮件的异常...",
  "entry_repo": "ts-preserve-service",
  "ground_truth": {
    "direct": ["ts-preserve-service", "ts-preserve-other-service", "ts-cancel-service"],
    "propagated": ["ts-notification-service"],
    "context": []
  },
  "commit_message": "fix: send email exception",
  "difficulty": "easy",
  "anti_bias_type": "none"
}
```

用例分布：

| 难度 | 数量 | ID |
|------|------|-----|
| easy | 9 | TT-001, TT-006, TT-008, TT-010, TT-011, TT-012, TT-013, TT-014, TT-015 |
| medium | 4 | TT-003, TT-005, TT-007, TT-009 |
| hard | 2 | TT-002, TT-004 |

| 对抗类型 | 数量 | ID |
|---------|------|-----|
| none | 7 | TT-001, TT-003, TT-004, TT-008, TT-010, TT-011, TT-014 |
| cross-domain | 4 | TT-002, TT-005, TT-009, TT-013 |
| trap | 3 | TT-006, TT-012, TT-015 |
| synonym | 1 | TT-007 |

### 2.2 datasets/train-ticket/call_graph.json

- 来源：对 train-ticket 源码静态提取 RestTemplate 调用关系
- 内容：`call_graph`（45 节点，90 条边）+ `reverse_call_graph`（反向索引）
- 用途：为 propagated 层 Ground Truth 提供调用链依据

### 2.3 datasets/train-ticket/scoring.py

- 输入：validation_cases.json + RepoMesh 的输出（仓库列表）
- 输出：按用例明细 + 按难度分组 + 按对抗类型分组 + 整体汇总
- 评分公式：Recall = 0.6×direct + 0.2×propagated + 0.2×context
- 内置 `--self-test` 验证公式正确性
- 纯标准库实现，无外部依赖

### 2.4 datasets/cerny-backup/README.md

说明 Cerny Zenodo 备用数据集的来源、内容、暂不采用的原因、后续可借鉴点。

## 三、GitLab 拆分推送方案

### 3.1 目标

```
GitLab group: repomesh-train-ticket
URL: https://gitlab.metaglobal.cn/repomesh-train-ticket
Group ID: 1549
```

### 3.2 拆分脚本

脚本位置：`datasets/split_and_push.ps1`

对每个 ts-* 子目录执行：
1. `git clone --no-hardlinks` 复制完整仓库
2. `git filter-branch --subdirectory-filter <svc> -- --all` 提取子目录历史
3. 清理 filter-branch 备份（refs/original + reflog + gc）
4. 调用 GitLab API 创建空仓库
5. `git push -u origin --all` 推送

### 3.3 执行方式

```powershell
# 设置环境
$env:GITLAB_TOKEN = "glpat-xxxxx"

# 运行拆分推送
.\datasets\split_and_push.ps1
```

### 3.4 预期结果

- 45 个独立仓库推送到 repomesh-train-ticket group
- 每个仓库保留完整 commit 历史
- 每个仓库包含 pom.xml + src/ + Dockerfile

## 四、端到端测试方案（推送完成后执行）

### 4.1 测试流程

```bash
# 1. 设置环境变量
export GITLAB_TOKEN=glpat-xxxxx
export DEEPSEEK_API_KEY=sk-xxxxx

# 2. 逐个跑验证用例
for case in TT-001 TT-002 ... TT-015; do
    repomesh run --no-interactive \
        -r "$(jq -r '.[] | select(.id=="'$case'") | .requirement' datasets/train-ticket/validation_cases.json)" \
        https://gitlab.metaglobal.cn/repomesh-train-ticket \
        > output_$case.json
done

# 3. 评分
python datasets/train-ticket/scoring.py --predictions-dir ./outputs/
```

### 4.2 预期指标

| 指标 | 目标 |
|------|------|
| 整体 Recall | ≥ 80% |
| 整体 Precision | ≥ 60% |
| easy 用例 Recall | ≥ 90% |
| hard 用例 Recall | ≥ 70% |

### 4.3 失败分析

对每个失败用例检查：
- direct 漏掉的 → LLM 为什么没发现？AutoCard 信息够不够？
- propagated 漏掉的 → 调用链追踪逻辑有没有问题？
- 多报的（Precision 下降）→ LLM 幻觉还是 Ground Truth 不全？
