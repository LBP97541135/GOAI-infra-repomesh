## 三、CLI 用法

```bash
# 文本描述方式
repomesh run -r "修复支付回调超时的问题" https://gitlab.example.com/group

# 需求文档方式
repomesh run -f PRD.md https://github.com/org/repo

# 省略 URL，交互式提示
repomesh run -r "修复支付回调超时"
# → ⚠ 未提供仓库或组织 URL。
# → URL > _

# 无交互模式（CI/CD）
repomesh run --no-interactive -r "加退款功能" https://gitlab.example.com/group

# 本地扫描（调试用）
repomesh scan /path/to/repo
```

## 四、实施中的关键决策

### 4.1 解析失败时 fail-open

LLM 返回无效 JSON 时，`_parse_analysis()` 返回 `sufficient=True, confidence=0.5`。理由：

- 宁可放过（多分析一次），不可阻塞（用户卡在交互里出不来）
- 充分度评估是优化步骤，不是必须步骤

### 4.2 置信度阈值 0.7

即使 LLM 返回 `sufficient=true`，如果 `confidence < 0.7` 也会被强制设为 `sufficient=false`。理由：

- LLM 有时会过度自信（说 sufficient 但置信度只有 0.5）
- 0.7 是经验值，后续可根据验证集结果调整

### 4.3 交互轮次上限 2 轮

避免无限追问让用户烦躁。2 轮后强制进入分析，结果中标注低置信度仓库。

### 4.4 `parse_user_input` 保留

原函数不删除，因为已有 24 个测试依赖它。标注 deprecated，后续版本移除。
