# RepoMesh 仓库发现 — 一句话交互方案

**日期**: 2026-08-03
**作者**: chenwenhui

---

## 一、核心变化

从"用户手动注册仓库 + 手动发起发现"变成"**用户说一句话，系统全自动处理**"。

### 之前（已废弃）

```
用户手动 register → 用户手动 discover → 看结果
```

### 现在

```
用户输入一句话 → 系统解析 URL + 需求 → 自动拉仓库 → 自动构建 AutoCard → LLM 推理 → 输出
```

---

## 二、用户输入格式

用户输入一句话，包含需求 + URL：

```bash
# 情况 A：单仓库 URL（场景一 — 入口追溯）
python scripts/repomesh_cli.py run "在 https://gitlab.metaglobal.cn/orders/order-service 里加微信支付"

# 情况 B：组织/组 URL（场景二 — 全量定位）
python scripts/repomesh_cli.py run "在 https://gitlab.metaglobal.cn/orders/ 里加微信支付"
```

## 三、完整流程

```
用户输入一句话
  │
  ▼
① 解析输入：提取 URL + 需求文本
  │
  ├─ URL 是单仓库？（调 API 验证）
  │   YES → 往上找父级组/组织
  │        → 拉取同组全部仓库
  │        → 该仓库标记为入口（is_entry_point=true）
  │
  └─ URL 是组织/组？（调 API 验证）
      YES → 拉取该组织全部仓库
          → 无入口
  │
  ▼
② 检查本地缓存（.repomesh_cache/{org_hash}/）
  │
  ├─ 有缓存且 < 24h？
  │   YES → 直接用缓存中的 AutoCard
  │
  └─ 无缓存或已过期？
      → 提示 "正在扫描仓库..."
      → 并行构建 AutoCard（每仓库 2~3 次 API，并发 5）
      │
      │  每仓库的 AutoCard 构建：
      │  ┌─────────────────────────────────────────────────────┐
      │  │ 第 1 次 API：GET 文件树                              │
      │  │  GitLab:  GET /projects/:id/repository/tree          │
      │  │  GitHub:  GET /repos/:owner/:repo/git/trees/:branch  │
      │  │  → top_dirs：取第一层 type=tree 的路径名              │
      │  │  → 发现依赖文件是否存在（requirements.txt? package.json?）│
      │  │                                                      │
      │  │ 第 2 次 API：GET commits                             │
      │  │  GitLab:  GET /projects/:id/repository/commits       │
      │  │  GitHub:  GET /repos/:owner/:repo/commits            │
      │  │  → recent_commits：取最近 5 条 commit message         │
      │  │                                                      │
      │  │ 第 3 次 API（如有依赖文件）：GET 文件内容              │
      │  │  GitLab:  GET /projects/:id/repository/files/:path   │
      │  │  GitHub:  GET /repos/:owner/:repo/contents/:path     │
      │  │  → deps：解析 requirements.txt / package.json / go.mod│
      │  │                                                      │
      │  │ 不扫的：                                              │
      │  │  exposed_apis = 空（需逐源文件读，代价高，V1 做）       │
      │  │  languages = 从依赖文件推断                           │
      │  │                                                      │
      │  │ low_signal 评分（满分 0.9，无 exposed_apis）：        │
      │  │  +0.3 仓库名含业务关键词                             │
      │  │  +0.3 top_dirs 有业务目录名                          │
      │  │  +0.2 deps 有非框架包                                │
      │  │  +0.2 commits 有具体内容                             │
      │  │  总分 < 0.3 → low_signal = True                     │
      │  └─────────────────────────────────────────────────────┘
      │
      ├─ 过滤 archived / empty / fork
      ├─ 进度提示 "正在扫描 3/27..."
      └─ 存缓存
  │
  ▼
③ LLM 推理（一次调用，temperature=0）
  │
  ├─ prompt 组装：
  │   系统："你是仓库发现助手，返回 JSON 数组..."
  │   用户：
  │     "## 仓库列表
  │      ### order-service
  │      - top_dirs: src, src/api, src/models
  │      - deps: fastapi, stripe, payment-sdk
  │      - recent_commits: feat: add multi-currency | fix: cart total
  │      - low_signal: FALSE
  │
  │      ### payment-service
  │      - deps: stripe, wechatpay
  │      - recent_commits: feat: refund flow
  │
  │      ### svc-3721
  │      - deps: fastapi
  │      - recent_commits: update, fix bug
  │      - low_signal: TRUE
  │
  │      ## 需求
  │      在 order-service 里加微信支付    ← 入口标记（系统从 URL 解析）
  │
  │      ⚠️ 以下仓库信息量不足：svc-3721
  │
  │      ## 任务（prompt 分两种场景，系统决定，不由 LLM 猜）
  │      有入口 → "order-service 是入口仓库，找出改动会波及的其他仓库"
  │      无入口 → "找出与需求相关的所有仓库""
  │
  ├─ LLM 输出 JSON 数组
  ├─ 幻觉过滤：仓库名不在列表里的 → 丢弃
  ├─ 入口仓库强制 confidence=1.0
  └─ 自纠正重试：JSON 解析失败时重试一次
  │
  ▼
④ 输出结果 + low_signal 提示 → 人工确认

  候选仓库：
    [确定] order-service           — 入口
    [0.88] payment-service         — order-service 依赖 payment-sdk
    [0.65] notification-service    — 支付成功触发通知

  ⚠️ 信息量不足，建议人工检查：
    [?] svc-3721
```

## 四、缓存策略

```
第一次（冷启动）：
  全量构建所有仓库 AutoCard → 存缓存 → 耗时 1-2 分钟

第二次（缓存未过期 <24h）：
  直接读缓存 → 0 次 API → 秒出

缓存过期（>24h）：
  提示 "缓存已过期，是否刷新？"
  ├─ 刷新 → 重新全量构建
  └─ 跳过 → 用旧缓存继续

V1（增量更新，跟依赖图一起做）：
  缓存里存每个仓库的 last_commit_sha
  拉取时比对 sha，变了才重新扫描
```

缓存省的是 API 调用和等待时间，不省 LLM token（prompt 内容一样）。

### 第一步：平台适配层（infrastructure/platform/）

新增文件：

```
src/repomesh/modules/repository_intelligence/infrastructure/platform/
├── __init__.py
├── fetcher.py          ← PlatformFetcher 协议 + 数据结构
├── gitlab_fetcher.py   ← GitLab API 实现
└── github_fetcher.py   ← GitHub API 实现
```

PlatformFetcher 协议：

```python
class PlatformFetcher(Protocol):
    async def identify(self, url: str) -> UrlType:
        """判断 URL 是单仓库还是组织/组。返回 SINGLE_REPO / GROUP / UNKNOWN"""

    async def fetch_parent_group_url(self, repo_url: str) -> str | None:
        """单仓库 URL → 返回父级组的 URL。"""

    async def list_repos(self, group_url: str) -> list[RepoInfo]:
        """列出组/组织下所有仓库。返回 name + url + description + archived + empty。"""

    async def fetch_file_tree(self, repo_url: str) -> list[str]:
        """返回文件路径列表。"""

    async def fetch_commits(self, repo_url: str, limit: int = 5) -> list[str]:
        """返回最近 N 条 commit message。"""

    async def fetch_file_content(self, repo_url: str, file_path: str) -> str | None:
        """返回指定文件的文本内容。文件不存在返回 None。"""
```

GitLab API 映射：

| 协议方法 | GitLab API |
|---------|-----------|
| identify | GET /projects/:id（200=仓库）/ GET /groups/:id（200=组） |
| fetch_parent_group_url | 从 repo 的 namespace 信息取父组 URL |
| list_repos | GET /groups/:id/projects?per_page=100&archived=false |
| fetch_file_tree | GET /projects/:id/repository/tree?recursive=true&per_page=100 |
| fetch_commits | GET /projects/:id/repository/commits?per_page=5 |
| fetch_file_content | GET /projects/:id/repository/files/:path/raw |

GitHub API 映射：

| 协议方法 | GitHub API |
|---------|-----------|
| identify | GET /repos/:owner/:repo（200=仓库）/ GET /orgs/:org（200=组织） |
| fetch_parent_group_url | 从 repo 的 owner 信息取组织 URL |
| list_repos | GET /orgs/:org/repos?per_page=100&type=all |
| fetch_file_tree | GET /repos/:owner/:repo/git/trees/:branch?recursive=1 |
| fetch_commits | GET /repos/:owner/:repo/commits?per_page=5 |
| fetch_file_content | GET /repos/:owner/:repo/contents/:path |

认证：`GITLAB_TOKEN` / `GITHUB_TOKEN` 环境变量。

### 第二步：远程 AutoCard 构建（application/scan_remote.py）

新增文件：

```python
async def scan_remote(
    repo_info: RepoInfo,
    fetcher: PlatformFetcher,
) -> tuple[RepositoryProfile, AutoCard]:
    """对一个远程仓库构建 AutoCard。2~3 次 API 调用。"""

async def scan_org(
    group_url: str,
    fetcher: PlatformFetcher,
    *,
    on_progress: Callable[[int, int, str], None] | None = None,
) -> list[RepositoryProfile]:
    """拉取组织下所有仓库，并行构建 AutoCard。
    过滤 archived / empty / fork。
    并发 5 个，通过 on_progress 回调报告进度。
    """
```

scan_remote 内部逻辑：

```python
# 第 1 次 API：文件树
file_tree = await fetcher.fetch_file_tree(repo_url)
top_dirs = extract_top_dirs(file_tree)           # 取第一层目录名
dep_files = find_dep_files(file_tree)             # 找 requirements.txt / package.json / go.mod

# 第 2 次 API：commits
recent_commits = await fetcher.fetch_commits(repo_url)

# 第 3 次 API（如有）：依赖文件内容
deps = []
for dep_file in dep_files:
    content = await fetcher.fetch_file_content(repo_url, dep_file)
    deps.extend(parse_deps(dep_file, content))

# 算 low_signal
low_signal = compute_low_signal(repo_name, top_dirs, deps, recent_commits)

return AutoCard(
    top_dirs=top_dirs,
    deps=deps,
    recent_commits=recent_commits,
    exposed_apis=(),          # 远程不扫
    low_signal=low_signal,
)
```

### 第三步：缓存层（infrastructure/cache.py）

新增文件：

```python
class OrgCache:
    """按组织 URL 分目录的 AutoCard 缓存。
    存储路径：.repomesh_cache/{org_hash}/{repo_name}.json
    每个 JSON 包含：profile + auto_card + timestamp + last_commit_sha
    """

    def load(self, org_url: str) -> list[RepositoryProfile] | None:
        """读取缓存。返回 None 表示缓存不存在或已过期。"""

    def save(self, org_url: str, profiles: list[RepositoryProfile]) -> None:
        """写入缓存。"""

    def is_expired(self, org_url: str, max_age_hours: int = 24) -> bool:
        """检查缓存是否过期。"""
```

### 第四步：CLI 改造（scripts/repomesh_cli.py）

`run` 命令内部流程：

```python
def cmd_run(args):
    user_input = args.prompt

    # ① 解析输入
    url, requirement = parse_user_input(user_input)
    platform = detect_platform(url)          # gitlab / github / local

    # ② 确定 URL 类型 + 拉取仓库列表
    fetcher = make_fetcher(platform)
    url_type = await fetcher.identify(url)

    if url_type == SINGLE_REPO:
        entry_repo_name = infer_name(url)
        group_url = await fetcher.fetch_parent_group_url(url)
    else:
        entry_repo_name = None
        group_url = url

    # ③ 加载或构建缓存
    cache = OrgCache()
    profiles = cache.load(group_url)
    if profiles is None:
        profiles = await scan_org(
            group_url, fetcher,
            on_progress=lambda i, total, name: print(f"  扫描 {i}/{total}: {name}"),
        )
        cache.save(group_url, profiles)

    # ④ LLM 推理
    service = RepositoryDiscoveryService(
        InMemoryRepositoryCatalog(profiles),
        llm_client=make_llm_client(api_key),
    )
    results = await service.discover(
        requirement,
        entry_point=entry_repo_name,  # None 表示场景二
    )

    # ⑤ 输出
    print_results(results, profiles)
```

## 八、废弃的功能

| 废弃 | 原因 |
|------|------|
| `register` 命令 | 用户不需要手动注册，一句话自动完成 |
| `register-bulk` 命令 | 同上 |
| `list` 命令 | 不需要独立查看注册表，run 时自动展示 |
| `clear` 命令 | 缓存自动管理，过期提示刷新 |
| `.repomesh_registry.json` | 换成 `.repomesh_cache/` 缓存目录 |
| `run_mvp_validation.ps1` | 被新的 run 命令替代 |
