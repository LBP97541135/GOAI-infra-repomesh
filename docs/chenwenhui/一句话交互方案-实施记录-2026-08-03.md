## 一、完成了什么

把仓库发现从"手动注册 + 手动发现"改造成"用户说一句话，系统全自动处理"。

用户只需要：

```bash
python scripts/repomesh_cli.py run "在 https://gitlab.metaglobal.cn/orders/order-service 里加微信支付"
```

系统自动完成：解析 URL → 判断单仓库/组织 → 拉取仓库列表 → 构建 AutoCard → 缓存 → LLM 推理 → 输出候选 + low_signal 提示。

## 五、架构

```
用户输入一句话
  │
  ▼
① parse_user_input() → 提取 URL + 需求文本 + entry_repo_name
  │
  ▼
② detect_platform() → GitLab / GitHub / LOCAL
  │
  ▼
③ fetcher.identify(url) → SINGLE_REPO / GROUP
  ├─ SINGLE_REPO → fetcher.fetch_parent_group_url() → 找父组
  └─ GROUP → 直接用
  │
  ▼
④ OrgCache.load(group_url)
  ├─ 有缓存(<24h) → 直接用
  └─ 无缓存 → scan_org()
      ├─ fetcher.list_repos() → 拉列表
      ├─ 过滤 archived/empty/fork
      └─ 并发 scan_remote() (5个)
          ├─ fetch_file_tree → top_dirs + dep_files
          ├─ fetch_commits → recent_commits
          └─ fetch_file_content → deps
  │
  ▼
⑤ RepositoryDiscoveryService.discover(requirement, entry_point=...)
  ├─ build_discovery_prompt() → 分场景 prompt
  ├─ LLM 推理 → JSON
  ├─ 幻觉过滤 + JSON 容错
  └─ _ensure_entry_point() → 入口强制 1.0
  │
  ▼
⑥ 输出候选 + low_signal 提示
```

## 六、远程 AutoCard 字段

| 字段 | 来源 | API 调用 |
|------|------|---------|
| top_dirs | 文件树 → 取第一层目录 | 1 次 |
| deps | 文件树发现依赖文件 → 读内容 | 0~2 次 |
| recent_commits | commits API | 1 次 |
| exposed_apis | 远程不扫 | 0 次 |
| low_signal | 基于 top_dirs + deps + commits 评分 | 0 次 |

每仓库总计 2~3 次 API 调用。low_signal 满分 0.9（无 exposed_apis），阈值 0.3 不变。

## 七、两种场景的 prompt 差异

### 场景一（单仓库 URL，有入口）

```
## Entry Point

The user has confirmed that changes will start in **order-service**.
Include order-service in your results with confidence 1.0. Then find
all OTHER repositories that may be affected by changes to order-service.
```

入口仓库由系统从 URL 解析得出，不由 LLM 猜。

### 场景二（组织 URL，无入口）

```
## Requirement

加微信支付
```

LLM 全量匹配。

## 八、缓存

```
.repomesh_cache/{org_hash}/
├── _meta.json          ← 版本 + 时间戳 + 仓库数
├── order-service.json  ← profile + auto_card
├── payment-service.json
└── ...
```

- 24h 过期，过期后提示刷新
- 不省 LLM token（prompt 内容一样），省的是 API 调用和等待时间
- V1 做增量更新（比对 last_commit_sha）
