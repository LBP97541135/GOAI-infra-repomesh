## 三、验证集设计

### 3.1 数据来源筛选

从 train-ticket 的 323 个 commit 中，按以下标准筛选：

| 档位 | 标准 | 数量 |
|------|------|------|
| 第一档 | commit message 有明确业务语义，接近需求描述 | 7 个 |
| 第二档 | commit message 模糊（"fix bug"），但从 diff 能逆推业务含义 | 8 个 |
| 合计 | | **15 个** |

排除标准：
- 改动 < 2 个服务的 commit（区分度不够）
- 改动 > 15 个服务的 commit（大重构，几乎所有服务都命中，区分度为零）
- 纯 merge commit、纯文档修改

### 3.2 需求描述粒度

采用**业务语言**，不暴露技术细节：

- ❌ "优化订票流程"（太模糊）
- ✅ "修复订票流程中发送通知邮件的异常，用户反馈下单后收不到确认邮件"
- ❌ "修改 PreserveServiceImpl 的 sendEmail 调用"（直接给答案）

需求描述从 commit message + git diff 内容逆向构造，扩展为 2~5 句的业务描述。

### 3.3 Ground Truth 三层结构

| 层次 | 含义 | 来源 | 评分权重 |
|------|------|------|---------|
| **direct** | commit 实际改了文件的仓库 | `git diff --name-only` | 0.6 |
| **propagated** | 调用链上受影响但未直接修改的仓库 | `call_graph.json` 下游 | 0.2 |
| **context** | 同业务域可能需要配合修改的仓库 | 人工判断 | 0.2 |

### 3.4 对抗性测试

| 类型 | 用例数 | 目的 |
|------|--------|------|
| synonym（同义替换） | 1 | 需求说"支付"但答案里没 payment-service |
| trap（陷阱） | 3 | 入口仓库 ≠ 实际要改的仓库 |
| cross-domain（跨域传播） | 4 | 需求只涉及一个功能，Ground Truth 涉及远端 |
| none（基准） | 7 | 正常测试 |

### 3.5 评分公式

```
Recall = 0.6 × direct_recall + 0.2 × propagated_recall + 0.2 × context_recall
Precision = len(predicted ∩ all_truth) / len(predicted)
F1 = 2 × Precision × Recall / (Precision + Recall)
```

### 3.6 难度分级

| 难度 | 用例数 | 标准 | 预期 Recall | 预期 Precision |
|------|--------|------|------------|---------------|
| easy | 9 | direct ≤ 3 | ≥ 90% | ≥ 70% |
| medium | 4 | direct 4~8 | ≥ 80% | ≥ 60% |
| hard | 2 | direct ≥ 9 或跨域 | ≥ 70% | ≥ 50% |

## 五、GitLab 部署方案

### 为什么需要推到 GitLab

RepoMesh 的生产流程是通过 PlatformFetcher 调用 GitLab/GitHub API 获取仓库信息。train-ticket 是单体仓库，需要拆成 45 个独立仓库才能真实模拟。

### 部署目标

```
GitLab group: repomesh-train-ticket（ID=1549）
├── ts-admin-basic-info-service       ← 独立仓库，含完整 commit 历史
├── ts-admin-order-service
├── ...
├── ts-preserve-service
└── ...（共 45 个）
```

### 拆分方法

使用 `git filter-branch --subdirectory-filter` 对每个子目录提取完整 commit 历史：

```bash
git clone --no-hardlinks train-ticket-full ts-cancel-service
cd ts-cancel-service
git filter-branch --prune-empty --subdirectory-filter ts-cancel-service -- --all
git remote add origin https://gitlab.metaglobal.cn/repomesh-train-ticket/ts-cancel-service.git
git push -u origin --all
```

### 队友使用方式

```bash
# 设置 token
export GITLAB_TOKEN=glpat-xxxxx

# 运行验证集
repomesh run -r "修复订票流程中发送通知邮件的异常" \
    https://gitlab.metaglobal.cn/repomesh-train-ticket

# 评分
python datasets/train-ticket/scoring.py
```
