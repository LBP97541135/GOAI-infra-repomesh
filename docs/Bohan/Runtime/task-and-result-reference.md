# RunnerTask and Result Reference (runtime.v1)

Worked examples and field semantics for the two shapes that cross the
RepoMesh ⇄ Runner boundary. The JSON schemas in this package remain the
machine-checked source of truth; this document is the human-readable companion.
Every example below was generated by the Python implementation
(`RunnerTask.to_wire()` / `RunnerEvent.to_wire()`), not written by hand.

Producers: RepoMesh composes a RunnerTask; the Runner posts RunnerEvents back.
Naming: wire keys are camelCase; the Python dataclasses use snake_case.
Optional keys may be **absent or explicitly null — the parser treats both
identically** (additive-v1 compatibility).

---

## 1. RunnerTask (RepoMesh → Runner)

A fully populated task:

```json
{
  "schemaVersion": "runtime.v1",

  "organizationId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "projectId":      "3f1a8b22-91d4-4c3e-8a01-5b7e2d9c4f10",
  "taskId":         "a1b2c3d4-5e6f-4a8b-9c0d-1e2f3a4b5c6d",
  "runId":          "9f8e7d6c-5b4a-4392-8180-7f6e5d4c3b2a",
  "correlationId":  "0e1d2c3b-4a59-4687-9584-3a2b1c0d9e8f",
  "attempt": 1,

  "adapterId": "claude-code",
  "instruction": "Complete the current task spec: fix the pricing rounding rule and cover it with tests.",

  "repository": {
    "repositoryId": "5d4c3b2a-1908-4e7f-a6d5-c4b3a2918070",
    "url": "https://github.com/acme/pricing-service.git",
    "baseRevision": "main"
  },

  "workspace": {
    "workspaceId": "ws-91f3a7c2",
    "path": "/srv/repomesh/worktrees/pricing-service/9f8e7d6c",
    "baseSha": "9f2c1ab7e3d4568a0b1c2d3e4f5a6b7c8d9e0f1a"
  },

  "contextBundle": {
    "bundleId": "2b3c4d5e-6f70-4182-9394-a5b6c7d8e9f0",
    "version": 3,
    "manifestUri": "s3://repomesh-bundles/2b3c4d5e/v3/manifest.json",
    "contentHash": "sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
    "codingPackageHash": "sha256:2c26b46b68ffc68ff99b453c1d30413413422d706483bfa0f98a5e886266e7ae"
  },

  "permissions": {
    "mode": "accept_edits",
    "allowedTools": ["read", "edit", "test"],
    "disallowedTools": ["git-push"],
    "allowedPaths": ["src/pricing/**", "tests/pricing/**"],
    "deniedPaths": [".github/**", "infra/**"],
    "networkTargets": []
  },

  "testCommands": ["pytest tests/pricing", "ruff check src/pricing"],
  "resumeSessionId": "d76b674d-9bfa-4405-8b01-54d0c5fb8f8d",
  "credentialRefs": ["github-app-token", "anthropic-api-key"],
  "workerAgentId": "6a7b8c9d-0e1f-4203-8415-263748596a7b",

  "idempotencyKey": "a1b2c3d4:run:9f8e7d6c:attempt:1",
  "issuedAt": "2026-08-05T12:30:45+00:00"
}
```

### Field constraints (violations are rejected at parse time)

| Field | Constraint |
| --- | --- |
| `schemaVersion` | must equal `runtime.v1`; any other value rejects the whole task |
| `attempt` | ≥ 1 |
| `adapterId` | a registered profile id: `claude-code`, `codex`, `kimi` (`mock` is validation-only) |
| `instruction`, `idempotencyKey` | non-empty |
| `issuedAt` | must carry a timezone |
| every `*Hash` | `sha256:` + 64 lowercase hex characters |
| every string array | non-empty elements, no duplicates |
| `permissions.mode` | `default` \| `accept_edits` \| `auto` \| `bypass_permissions` |
| `workspace.path` | absolute; the directory must already exist — the Runner validates, never creates |
| `credentialRefs` | reference **names** only; credential values never enter the contract |

### Semantics

- **Workspace is the single source of truth when present** (decision D1). The
  Runner resolves the path, requires it to be strictly inside its configured
  workspace root (escape and symlink tricks rejected), and never clones;
  `repository.url` / `baseRevision` are then reference metadata. Without a
  `workspace`, the transitional fallback creates `{workspace_root}/{runId}`,
  which carries no isolation guarantee.
- **`permissions.mode` decides how much to ask, never how much is allowed**
  (decision D2/D3). Precedence:
  `deniedPaths > disallowedTools > allowedPaths > allowedTools > mode`.
  Deny rules bind in every mode, including `bypass_permissions`; bypass only
  removes the interactive confirmation step. No profile maps a CLI's own
  bypass flag, because those flags silence the permission-callback channel the
  deny rules are enforced on.
- **`idempotencyKey` is the at-most-once execution key.** The Runner records
  it in a local ledger; redelivering the same key is a no-op (no re-execution,
  no re-emitted events). The same attempt must reuse the same key; a new key
  means a new execution.
- **`resumeSessionId`** carries a `nativeSessionId` from a previous run's
  events. The executor forwards it only for profiles whose `resumable`
  capability was verified against the real CLI (all three vendor profiles,
  measured 2026-08-05, including resume after a killed process). An unknown id
  fails loudly — no CLI silently starts a fresh session.

## 2. Results (Runner → RepoMesh)

There is no HTTP response body. The Runner reports through **ordered
RunnerEvents** POSTed to the event sink, each with an HTTP header
`Idempotency-Key: {idempotencyKey}:event:{sequence}`. The `eventId` is derived
(UUIDv5) from that key, so a redelivered event keeps its id and the receiver
can deduplicate on either.

### Envelope vs payload

Every event has the same **envelope** (top-level keys): routing and ordering
facts a receiver uses without inspecting the content — `eventType`,
`taskId`/`runId`/`correlationId`, `attempt`, `sequence`, `occurredAt`, and
`nativeSessionId`. The **`payload`** differs per event type.

`nativeSessionId` lives on the envelope, not in the payload, because it is
meaningful on *every* event type: drivers announce the session id the moment
the CLI reports it (event time, not turn end), so a mid-turn crash still
leaves the id with the platform — which is exactly when resume is needed.

### Example: acceptance (first event of every run)

```json
{
  "schemaVersion": "runtime.v1",
  "eventId": "87e43613-07cb-5a0a-b59d-7bf54550bf8f",
  "eventType": "runner.accepted",
  "organizationId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "projectId": "3f1a8b22-91d4-4c3e-8a01-5b7e2d9c4f10",
  "taskId": "a1b2c3d4-5e6f-4a8b-9c0d-1e2f3a4b5c6d",
  "runId": "9f8e7d6c-5b4a-4392-8180-7f6e5d4c3b2a",
  "correlationId": "0e1d2c3b-4a59-4687-9584-3a2b1c0d9e8f",
  "attempt": 1,
  "sequence": 1,
  "occurredAt": "2026-08-05T12:30:46.101000+00:00",
  "nativeSessionId": null,
  "payload": { "adapterId": "claude-code" }
}
```

### Example: terminal event carrying the structured result

```json
{
  "schemaVersion": "runtime.v1",
  "eventId": "35edf779-4a3e-5d4c-b982-00a018f82975",
  "eventType": "runner.failed",
  "taskId": "a1b2c3d4-5e6f-4a8b-9c0d-1e2f3a4b5c6d",
  "runId": "9f8e7d6c-5b4a-4392-8180-7f6e5d4c3b2a",
  "attempt": 2,
  "sequence": 2,
  "occurredAt": "2026-08-05T12:34:59.622000+00:00",
  "nativeSessionId": "019fd1bb-ff7e-7750-b6a7-8eaa46cb755b",
  "payload": {
    "status": "failed",
    "summary": "test_command_failed: pytest tests/pricing (exit code 1)",
    "changedFiles": ["src/pricing/api.py"],
    "testResults": [
      { "command": "pytest tests/pricing",   "exitCode": 1 },
      { "command": "ruff check src/pricing", "exitCode": 0 }
    ],
    "artifacts": [],
    "testCommand": null
  }
}
```

Terminal event types map one-to-one onto `payload.status`:
`runner.completed`→`succeeded`, `runner.failed`→`failed`,
`runner.interrupted`→`interrupted`, `runner.input_required`→`input_required`.
The remaining defined types (`runner.session_started`, `runner.progress`,
`runner.test_completed`) are reserved for a future progress stream; today the
engine emits acceptance plus one terminal event.

### The in-process shape behind the payload

`RunnerExecutionResult` (Python, `src/repomesh_runner/contracts.py`) is what
the executor returns; the engine translates it into the terminal payload:

| Field | Payload key | Notes |
| --- | --- | --- |
| `status` | `status` | `succeeded` \| `failed` \| `interrupted` \| `input_required` |
| `summary` | `summary` | a failing verification command is named here |
| `native_session_id` | envelope `nativeSessionId` | the one field promoted out of the payload |
| `changed_files` | `changedFiles` | from `git status` in the workspace, guarded so a parent repository's dirt is never reported |
| `test_results` | `testResults` | `{command, exitCode}` per configured `testCommands` entry |
| `artifacts` | `artifacts` | reserved (`{kind, uri, contentHash}`); nothing populates it yet |
| `test_command` | `testCommand` | legacy, superseded by `testResults`; always null |

### Result semantics

- **A failed verification is a failed run.** When the driver succeeds but any
  `testCommands` entry exits non-zero, the overall status is `failed` and the
  summary names the first failing command. The evidence is still complete:
  all commands run, all exit codes and changed files are reported. An
  incomplete outcome is never wrapped as success.
- **`interrupted` still carries `changedFiles`** — a half-finished agent may
  have written files, and hiding that would make the workspace a black box.
- **`nativeSessionId: null` on a failure is information, not absence.** It
  means the session was never opened; retrying with resume is guaranteed to
  fail again. A failure that *does* carry the id means the session is alive
  and resumable. Measured trap behind this rule: one CLI echoes an unknown
  resume id back inside its error result, so ids are only trusted once the
  init frame confirmed the session — an echoed-but-never-opened id is dropped.
- Session ids are vendor-opaque strings, passed through unparsed, but
  sanitized before reuse (length-capped; leading `-` and control characters
  rejected) because they are later interpolated into resume command lines.
