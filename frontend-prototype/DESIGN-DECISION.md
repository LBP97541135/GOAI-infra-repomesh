# 前端设计决策（2026-08-11 定稿）

> 原型回答的问题：RepoMesh 交付控制台应该长什么样。
> 结论：**选定 Variant D「融合工作台 · 复古未来主义」**，A/B/C 落选但保留为一手材料。

## 胜出方案：Variant D

结构（三层职责：对话讲过程、卡片要决策、面板给事实）：

- **左栏**：深色项目树——交付列表、新建交付、Agent Runtime 状态、用户身份。
- **中栏 = 对话主线程**：PM/Analyst/QA/Release Guardian 的消息流，内嵌结构化
  artifact 卡（范围冻结卡、DAG 卡、失败卡+修复循环+治理拦截、审批卡）。
  顶部有**视图切换**：`房间`（对话流）↔ `DAG · 计划`（阿波罗飞行计划风格的
  奶油纸面文档：1.0 目标验收 / 2.0 变更范围 / 3.0 DAG / 4.0 执行计划 / 5.0 回滚预案）。
- **决策夹（签名元素）**：VARIADEX 档案柜隐喻——待决策事项是牛皮纸文件夹，
  堆叠收在输入框后方，彩色标签错位露头（审批=橄榄绿/关注=琥珀/澄清=赭红），
  点后排置顶、可整堆收起、处理完即消化移除。
- **悬浮环境窗（Codex 式）**：浮在右上角，可折叠。内容：关联仓库（每仓 diff
  文件明细）→ ChangeSet（PR/合并状态）→ 环境（预发/快照/Matrix/成本）→ 后台进程。
- **审批弹窗**：快照绑定授权单（授权主体、不可变快照、30 分钟有效期、写入范围、
  「任一 SHA/契约/门禁变化即失效」确认框）——治理故事的核心展示，保留。

## 视觉令牌（复古未来主义 · 硬朗）

- 色：暖黑 `#16130d` / 面板 `#201b12` / 琥珀 `#c99e52`（主色）/ 奶油纸 `#e9dec2`
  / 牛皮纸 `#dcc99c` / 赭红 `#c26d51` / 橄榄 `#94a35a` / 蓝灰 `#8aa0b4`（仅执行中）。
- 形：圆角全局 2px；平面色块按钮；hairline 边框；无柔和渐变阴影。
- 字：微标签一律等宽大写加字距；正文中文用系统 sans；id/路径/数字用等宽。
- 细节：米色 REC 状态卡 `● RUN 2H09M`；DAG 容器坐标网格底纹；纸面文档黑色数字节标。

## 落选方案与吸收

- A 流水叙事：落选；「治理拦截」黄条、修复循环时间线并入 D 的失败卡。
- B 指挥中心：落选；DAG 主视觉、事件流思路并入 D（事件流未来可进环境窗或房间流）。
- C 决策收件箱：落选；「等你决策」置顶理念演化为 D 的决策夹。
- 队友 7 月对话式原型（ref-agent-workspace.html）：对话主线程、悬浮上下文、
  快照审批单、场景切换器四个想法被吸收；其 7-9px 字号与七标签 Overview 被否决。

## 正式实现时的注意事项（原型未覆盖）

1. 原型是 throwaway 静态页，正式前端重写：建议 React + Vite + TS + Tailwind，
   DAG 用 React Flow 或保留手绘 SVG。
2. 后端缺读模型 API：交付全貌聚合、任务列表、runner 事件流、审计/证据查询；
   需要一组 `GET /api/v1/deliveries*`（见 2026-08-10 会话讨论）。
3. Demo 场景切换器（参考原型的 4 状态机）值得在正式版做成「回放模式」。
4. Trace 瀑布（Studio tRPC `getTrace`）留作二期，先展示 trace_id + 复制。
